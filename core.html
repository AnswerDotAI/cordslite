Discord has three APIs. The REST API handles actions such as sending a message, listing channels, or fetching history. The Gateway API pushes real-time events over a websocket. The Voice API streams audio over UDP.

The REST API needs a bot token from the Discord Developer Portal:

  1. Create an application.
  2. Under “Bot”, add a bot and copy its token.
  3. Under “OAuth2”, generate an invite URL with the bot scope and the permissions the bot needs, and open it to invite the bot to your server.

DiscordClient wraps an httpx2 client with Discord’s base URL (https://discord.com/api/v10) and the auth header set.

Async client for Discord’s REST API

DiscordClient reads DISCORD_BOT_TOKEN from the environment when it gets no token. Tokens are stripped of surrounding whitespace, since a pasted token often carries a trailing newline, and a blank token counts as absent.

dc = DiscordClient()
pasted = DiscordClient(token=' abc\n', user_token='\txyz ')
test_eq((pasted.token, pasted.user_token), ('abc', 'xyz'))
test_is(DiscordClient(token='x', user_token=' \n').user_token, None)

REST endpoints

Every REST call goes through _req. On 429 Too Many Requests it waits for Retry-After seconds and retries. Any other non-2xx response raises DiscordError with Discord’s error code, message, and HTTP status.

Discord’s REST endpoints return JSON with many fields. DiscordObject wraps the raw dict instead of declaring a property per field. Fields read as obj.name or obj['name']. __dir__ lists them for tab completion in notebooks. New fields Discord adds are available without a code change.

Discord’s hierarchy is guild, channel, message. A guild (server) contains channels. A channel contains messages. Each level has its own REST endpoints:

  • GET /guilds/{id}
  • GET /guilds/{id}/channels
  • GET /channels/{id}/messages
  • POST /channels/{id}/messages

Guild, Channel, and Message subclass DiscordObject and add a __repr__.

A DM is an ordinary channel in Discord’s API. create_dm posts to /users/@me/channels with a recipient_id and returns a standard Channel. send and messages work on it unchanged. In gateway events a DM message has no guild_id. A handler can tell DMs from guild messages by that missing field.

Reading a person’s own DMs needs that person’s account token, not a bot’s. DiscordClient reads DISCORD_USER_TOKEN from the environment, or takes user_token. With no bot token it authenticates every request as the user. With both, a call passes use_user=True to send the user token for that request. Discord’s terms forbid automating a user account, so keep this to reading your own messages, and expect the token to change when the password does.
