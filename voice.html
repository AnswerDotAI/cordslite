Voice uses three connections at once. The main gateway websocket (gc) requests the join and receives the voice server details. A second websocket to the voice server coordinates the session. A UDP connection carries the audio. Audio goes over UDP because low latency matters more than guaranteed delivery. VoiceClient owns the voice websocket and the UDP connection for one channel. The main GatewayClient delivers the join events to it.

The voice gateway has its own opcodes. voice_state asks the main gateway to join a channel. voice_identify authenticates with the voice server. select_protocol picks the encryption mode. speaking marks the start and end of audio. voice_heartbeat keeps the voice websocket alive.

The voice heartbeat differs from the main gateway’s. Protocol v8 requires seq_ack, the sequence number of the last message from the server. The heartbeat must start as soon as Hello arrives, before UDP setup. Otherwise the voice server closes the websocket with code 4006.

Discord needs the bot’s external IP and port, the address the internet sees after NAT. The bot sends a 74-byte UDP request holding its SSRC. Discord returns the same packet with the external address filled in:

Field Size Description
Type 2 bytes 1=request, 2=response
Length 2 bytes 70 (size of remaining fields)
SSRC 4 bytes Our audio stream identifier
Address 64 bytes Blank in request; our external IP in response
Port 2 bytes Blank in request; our external port in response

Discord sends no audio packets until the bot sends a Speaking event, even one with speaking=0.

The voice gateway runs two loops. _hb sends heartbeats at the interval Discord specifies and watches for ACKs. A missed ACK closes the socket with code 4000. That code preserves the session for a resume. _reconnect handles both resume and fresh reconnect. A resume keeps session_id, token, endpoint, the UDP socket, and the DAVE state. A fresh reconnect resets the audio session and re-runs _join for new server details. _listen schedules _reconnect as its own task. _reconnect therefore cancels _listen_task only when called from elsewhere. A reconnect that cancelled the task it runs in would kill itself. Failed attempts retry with exponential backoff, capped at 30 seconds. The counter resets once the client establishes or resumes a session. Recording state survives both paths. Per-user files keep accumulating across a reconnect, with a silence gap during the swap.

VoiceClient.reset_audio

def reset_audio():

_listen runs the voice gateway state machine. On HELLO (op 8) it sends voice_resume if self.resuming holds and voice_identify otherwise. Op 9 confirms the resume at the gateway level. Media encryption is a separate handshake. DAVE must catch up before outgoing audio can be encrypted again. The client waits on _wait_dave_ready before setting resumed.

When the socket closes, the close code decides the recovery (docs). Codes 4003 to 4006, 4009, and 4011 mean the session’s credentials are dead. The main gateway issues voice tokens per session. The client rejoins from scratch to get fresh ones. A resume with dead credentials loops. Live testing showed that a bad resume gets 4003 Not authenticated, not 4006. Code 4014 means an admin kicked or moved the bot, or Discord is swapping the voice server. The client must not reconnect to that endpoint. It waits for gateway events instead. Any other code, such as 4015 (voice server crashed), is transient. The client resumes. Recovery runs as a separate task. The dying listener never cancels its own reconnect. The listener logs handler errors and skips them. They do not stop it.

Audio arrives as RTP packets over UDP. Each packet has a 12-byte or longer RTP header, an encrypted payload, and a 4-byte nonce at the end. The header carries the sequence number, the timestamp, and the SSRC that identifies the speaker. The payload is Opus audio wrapped by DAVE, then encrypted with Discord’s transport key secret_key.

Decryption has two stages. The transport layer uses aead_xchacha20_poly1305_rtpsize. The cipher takes a 24-byte nonce. Only 4 bytes travel in the packet. The client pads them with 20 zero bytes. The plain RTP header is the AAD: authenticated, not encrypted. In rtpsize mode the AAD covers the 12-byte base header, any CSRC entries, and the 4-byte extension preamble only. The extension data itself is inside the encrypted payload. Its length is in the preamble, as a count of 32-bit words. Packets without the extension bit have no extension data. The frame that remains is DAVE-protected. self.dave.decrypt unwraps it using the user id from the SSRC map. Voice SPEAKING events fill that map. The result is the Opus payload.

A packet whose second byte is 0x78 is RTP voice data. Other values, such as 0xC9, are RTCP control packets for quality reporting. The client skips them.

An earlier version skipped a fixed 8 bytes of extension. It corrupted audio whenever the extension was not two words. On packets with no extension it discarded real Opus data. Discord offers no way to request a particular extension size. The cell below builds RTP packets by hand and runs them through the real cipher: extensions of 0, 2, and 3 words, no extension, and no DAVE session. Without DAVE the transport plaintext is the Opus frame.

_key = bytes(range(32))
def _mk_pkt(payload, ext_words=2, has_ext=True):
    hdr = struct.pack('>BBHII', 0x80 | (0x10 if has_ext else 0), 0x78, 1, 960, 1234)
    if has_ext: hdr += struct.pack('>HH', 0xBEDE, ext_words)
    n4 = (7).to_bytes(4, 'big')
    enc = xchacha_encrypt((bytes(4 * ext_words) if has_ext else b'') + payload, hdr, n4 + b'\0'*20, _key)
    return hdr + enc + n4
fvc = object.__new__(VoiceClient)
fvc.secret_key = _key
cases = [dict(ext_words=0), dict(ext_words=2), dict(ext_words=3), dict(has_ext=False)]
test_eq([fvc.decrypt(_mk_pkt(b'opus!', **kw), 0) for kw in cases], [b'opus!']*len(cases))

decode turns RTP voice packets into PCM and keeps each speaker’s stream in order without a jitter buffer. It compares RTP sequence numbers modulo 16 bits. It accepts wraparound from 65535 to 0. It drops duplicates and packets behind the last accepted sequence. A forward gap means packet loss. Small gaps use Opus packet-loss concealment. Larger gaps use silence.

decode decrypts and decodes a packet before its sequence and timestamp become accepted state. A corrupt packet cannot move the stream backwards or poison the next gap calculation. decode discards a reordered packet rather than buffering it. Recording stays simple at the cost of an occasional 20 ms loss.

silence

def silence(
    n_smpls:int, # 2 bytes per sample (s16le)
):

Recording opens one ffmpeg process per speaker and writes that speaker’s decoded PCM to its stdin. Each file covers the whole session. _written counts the samples on disk per user. Before each write the track is padded with silence up to the current wall-clock position. Audio therefore sits at the moment the user spoke it, whether the user joined late, paused, or left and rejoined. Padding happens only when a track is more than 200 ms behind. While someone is speaking, each packet appends its 20 ms and the track keeps pace. Arrival jitter never inserts silence mid-sentence. A packet whose SSRC has had no Speaking event yet has no owner, and is dropped rather than recorded under the SSRC.

start_recording drains the UDP queue first. Stale packets from before the recording never reach the new files.

stop_recording pads every track with silence out to the stop time. All files are then session length and aligned. It closes each ffmpeg stdin and waits for the process. That finalizes the containers. Without it the files can look valid but lack the buffered audio at the end.

Outgoing audio is the receive path in reverse. The client encodes PCM to Opus. It wraps the frame with DAVE when the E2EE session is ready. It encrypts the frame with Discord’s transport key and sends it as an RTP packet. A bot alone in a channel negotiates a DAVE protocol version but has no MLS group until the epoch starts. Until then clients send plain Opus. davey raises NotReady if asked to encrypt earlier. The same applies briefly during epoch transitions.

The RTP sequence, timestamp, and nonce advance by hand for each 20 ms frame. If they drift or repeat, Discord hears broken audio or nothing.

DAVE-wrapped frames end with the marker 0xFAFA. Whether the encoder output carries it must agree with dave.ready. A bot alone in the channel has a negotiated version but no epoch. It sends plain Opus.

test_eq(vc.encode(silence(spf)).endswith(b'\xfa\xfa'), vc.dave.ready)

The bot must tell Discord when it starts and stops speaking. When a transmission ends, the docs require five frames of Opus silence (0xF8 0xFF 0xFE). Without them receivers interpolate the tail of the audio into the next utterance. The result is an audible garbled blip at the end of playback. Audio that arrives in chunks, such as a realtime TTS feed, should pass end=False for all but the last chunk. The transmission then stays continuous. The finally clears the speaking flag if playback fails halfway through.
