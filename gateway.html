Gateway API

Real-time Discord events over the WebSocket gateway 
dc = DiscordClient()
gid = '1493461895615873044'
ch = await dc.channel('1493461896139903028')

The Gateway is Discord’s websocket for real-time events. The REST API answers requests. The Gateway pushes new messages, reactions, member joins, and other events as they happen.

The connection lifecycle:

  1. Fetch the websocket URL from /gateway/bot.
  2. Connect.
  3. Receive Hello with the heartbeat interval.
  4. Start the heartbeat loop.
  5. Send Identify with the token and intents.
  6. Receive Ready.

Intents tell Discord which events to send. They are bit flags combined with |. Intent names the full set from the gateway docs. GUILD_MEMBERS, GUILD_PRESENCES, and MESSAGE_CONTENT are privileged and must also be enabled in the Developer Portal.

GatewayClient holds one gateway connection. It fetches the websocket URL from /gateway/bot when constructed, and dispatches each event to the handler registered for its type with on.

Op builds gateway payloads. Discord expects JSON with an op field (operation code) and a d field (data). Op.identify() and Op.heartbeat() return payloads ready to send.

A gateway event is JSON with four fields. op is the operation code: 0 dispatch, 1 heartbeat request, 10 hello, 11 heartbeat ACK. t is the event type name, such as MESSAGE_CREATE, present only on dispatches. s is the sequence number, present only on dispatches. Heartbeats and resumes send it back. d is the payload.

The client tracks the latest s. Event wraps the JSON and converts known dispatch types to their wrapper classes through evt_typs.

The gateway runs two loops. _hb sends heartbeats at the interval Discord specifies and watches for ACKs. A missed ACK means the connection is dead. _hb closes it with code 4000. That code keeps the session valid for a Resume. _listen reads events and dispatches them by opcode. On disconnect it calls _reconnect to open a fresh websocket. The new connection sends Hello (op 10). The Hello handler restarts the heartbeat and sends Identify on a first connect or Resume when a session exists. Op 7 (Reconnect) takes the same path.

All reconnection goes through _reconnect. A resume closes with code 4000 and opens a socket to resume_gateway_url. A re-identify closes with 1000 and returns to the original gateway URL. Code 1000 invalidates the session. The Hello handler then takes over.

start opens the websocket and starts the listener. The listener handles Hello, starts the heartbeat, and sends Identify. Events drive the whole connection lifecycle.

Let’s now test that our gateway is getting events. Here is a simple handlers for new messages.

async def on_msg(msg):
    if msg.get('guild_id') != gid: return
    if not msg.author.get('bot'): return
    print(f"{msg.author['username']}: {msg.content}")

gc.on('MESSAGE_CREATE', on_msg)

The handler prints a message sent to the channel.

Next, a reconnect that resumes and one that re-identifies. The handler should still print after each.

await gc._reconnect(resume=True)
await asyncio.sleep(2)
await ch.send('Houston, do we have a problem?')

Message(id=1544802851937722498, author='DBuddy', content='Did we re-identify?')

Those reconnects were polite ones the client started. A real disconnect arrives as ConnectionClosed in the listener. The listener classifies the close code per the docs. Transient codes resume. 4007 and 4009 re-identify. 4004 and 4010 to 4014 (bad token, bad shard, bad intents) stop. Closing the live socket with a non-1000 code triggers the transient path. The heartbeat watchdog does the same on a dead connection. The listener should resume without help.

await gc.ws.close(code=4000)
await asyncio.sleep(3)
await ch.send('Back from the dead? (listener auto-resume)')
Message(id=1544802865732657222, author='DBuddy', content='Back from the dead? (listener …')

Identifying with a corrupted token gets close code 4004. The client must stop instead of retrying.

gc_bad = GatewayClient(intents, dc)
gc_bad.token = gc_bad.token[:-4] + 'zzzz'
await gc_bad.start()
for _ in range(30):
    if not gc_bad.running: break
    await asyncio.sleep(0.5)
assert not gc_bad.running
gateway closed: 4004 Authentication failed.

stop cancels both background tasks and closes the websocket with code 1000. That tells Discord to invalidate the session. A later start identifies from scratch.
